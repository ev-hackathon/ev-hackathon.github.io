# AI 충전 수요 예측 모델 (v3, 통합 모델)

충전소별 **1시간 후 이용률**을 LightGBM으로 예측해, 시뮬레이션 탭과 관제 화면의 요금 판정에 쓰도록 `data/forecast.json`으로 내보낸다.

- 코드: `utils/forecast.py`(데이터·특징·학습·평가·예측), `scripts/forecast.py`(실행)
- 실행: GitHub Actions가 사이트를 만들 때마다 자동 실행 → https://ev-hackathon.github.io/data/forecast.json
- 2시간 후 예측도 같은 형식으로 함께 낸다 → https://ev-hackathon.github.io/data/forecast_2h.json (target_time = 생성 시각 + 2시간)
- 로컬: `python -m scripts.forecast --history <history 폴더> --out data/forecast.json`

## 입력과 출력

**타깃**: 예측 대상 시각의 이용률 = 충전 중 ÷ (빈 충전기 + 충전 중), 0~1. 고장 충전기는 분모에서 뺀다.
만차 확률(빈 충전기 0대)은 별도의 분류 모델로 함께 예측한다.

| 입력 변수 | 내용 |
|---|---|
| `u0`, `usable0`, `fault0` | 지금 이용률, 정상 충전기 수, 고장 충전기 수 |
| `prev_u`, `prev_gap`, `recent24` | 직전 관측 이용률과 그 간격(시간), 최근 24시간 평균 이용률 |
| `hist_dow_hour`, `hist_hour`, `hist_mean`, `hist_full`, `hist_n` | 그 충전소의 과거 같은 시간대(평일/주말 구분) 평균, 같은 시간대 평균, 전체 평균, 만차 비율, 관측 수 |
| `hour0`, `hour_t`, `dow_t`, `weekend_t`, `horizon` | 지금 시각, 예측 대상 시각·요일·주말 여부, 예측 간격(시간) |
| `fast`, `price`, `region` | 급속 여부, 운영사 회원가, 시·군 |
| `temp`, `rain`, `humid` | 예측 대상 시각의 기온·강수량·습도 (학습: 기상청 ASOS 실측, 예측: 초단기예보) |

**출력** (`data/forecast.json`, schema_version 1 — 시뮬레이션 탭의 외부 예측 입력 형식과 같음)

```json
{
  "schema_version": 1,
  "model_name": "LightGBM 이용률 예측 v2 (현재값 결합)",
  "generated_at": "2026-11-03T17:37:00+09:00",
  "target_time": "2026-11-03T18:37:00+09:00",
  "horizon_hours": 1.0,
  "predictions": [
    {"station_id": "EC430006", "speed": "slow", "utilization": 0.2312, "p_full": 0.0391, "status": "여유"}
  ],
  "metrics": { "...": "아래 성능 평가 결과" }
}
```

- `status`: 관제와 같은 기준. 만차 확률 ≥ 0.5면 혼잡, 아니면 빈 충전기 비율(1 − 이용률) ≥ 50%면 여유, 그 밖은 보통.
- `p_full`, `status`, `metrics`는 추가 필드라 시뮬레이션 탭은 무시해도 된다.

## 통합 구조 (v3)

최종 예측 = **a × 현재 이용률 + b × 충북 LightGBM + c × 서울 사전학습 모델**

| 구성 | 학습 데이터 | 강점 |
|---|---|---|
| 충북 LightGBM (`utils/forecast.py`) | 충북 수집 기록 3주 + 날씨 | 충북 충전소별 시간대 습관, 날씨, 운영사 요금 |
| 서울 사전학습 모델 (`utils/seoul.py`, 조원 UP024365 방식) | 서울시 소유 충전기 2025년 1년치 충전 이력(213곳, 1시간 간격 155만 행) | 정확히 1시간 간격 1년치라 '1시간 뒤' 변화 패턴을 넉넉히 학습. 입력: 현재·1·2·24·168시간 전 이용률, 시각, 요일 |
| 현재 이용률 | – | 1시간 안에는 지금 상태가 가장 강한 단서 |

- 서울 모델은 조원 코드와 같은 방법으로 이 저장소에서 다시 학습해 `models/seoul_lgbm.txt`로 저장했다(재현 결과 서울 12월 테스트 RMSE 0.168, 현재값 유지 0.208 — 조원 결과와 동일).
- 충북에 적용할 때 1·2·24·168시간 전 값은 같은 충전소의 가장 가까운 기록(1·2시간: ±20분, 24·168시간: ±45분)을 쓰고 없으면 비워 둔다. 서울 모델은 지난 값 40%를 일부러 비워 학습해 빈 값에 강하다.
- 비율 a·b·c는 아래 1시간 검증에서 날마다 같은 무게로 본 RMSE가 가장 낮은 조합으로 자동으로 정한다(0.1 단위, 하루 한 번 재평가). 만차 확률은 현재 만차 여부와 분류 모델을 상태 정확도가 가장 높은 비율로 섞는다.
- 서울 예측을 충북 LightGBM의 입력 변수로 넣는 방식도 시험했지만 개선이 없었다(1시간 RMSE 0.274 → 0.273). 충북 학습 짝이 대부분 2시간 이상 간격이라 모델이 1시간용 신호를 잘 쓰지 못해, 예측값 단계에서 결합했다.

## 학습 방식

수집 간격이 일정하지 않아(지금까지 중앙값 약 3시간) 정확히 1시간 뒤 짝은 거의 없다. 그래서 같은 시·군의 두 수집 시각 중 간격이 **0.5~8시간인 모든 짝**을 학습에 쓰고 예측 간격을 변수로 넣었다. 예측할 때는 간격에 1시간을 넣는다.
2026-11-03부터 15분 간격 수집기(`.github/workflows/collect.yml`)를 돌려, 1시간 간격 짝이 계속 쌓이도록 했다.

과거 패턴 특징은 학습 구간 기록으로만 계산해 미래 정보가 새지 않게 했다. 평가는 마지막 5일을 떼어 두고, 그 이전 기록으로만 학습했다. 성능 평가는 하루 한 번 다시 하고, 예측 모델은 매번 전체 기록으로 다시 학습한다.

## 성능 (v3, 2026-11-04 기준)

검증은 두 가지로 했다.

**① 정확히 1시간 뒤 (45~75분)** — 수집이 촘촘했던 날(10.15, 10.20, 11.03)을 하루씩 통째로 빼고 나머지 날로 학습해 그날로 검증 (짝 24.8만 개)

| 방법 | MAE | RMSE | 상태 정확도 |
|---|---|---|---|
| **통합 (현재 0.2 + 충북 0.4 + 서울 0.4)** | 0.113 | **0.221** | 92.9% |
| 현재값 + 충북 LightGBM (v2, 각 0.5) | 0.107 | 0.226 | 92.4% |
| 서울 사전학습 모델 단독 | 0.113 | 0.228 | – |
| 충북 LightGBM 단독 | 0.132 | 0.274 | – |
| 현재값 유지 | **0.087** | 0.249 | **93.4%** |
| 과거 같은 시간대 평균 | 0.145 | 0.289 | – |

- 통합 모델의 RMSE는 현재값 유지보다 11%, v2보다 2% 낮다. 날짜별로는 10.15(0.235 → 0.229)·10.20(0.244 → 0.240)에서 v2보다 좋았고 11.03(0.114 → 0.118)은 조금 나빴다.
- 서울 모델 단독도 충북 LightGBM 단독보다 훨씬 낫다(0.228 vs 0.274). 1년치 1시간 간격 학습의 효과다.
- MAE와 상태 정확도는 여전히 현재값 유지가 조금 낫다. 대부분의 충전기가 1시간 동안 그대로 비어 있기 때문이다.
- 2시간 뒤(1.75~2.25시간, 10.19·10.20·10.25 검증): 통합 RMSE 0.193, 현재값 유지 0.226 (15% 낮음). 비율은 현재 0 + 충북 0.4 + 서울 0.6.

**② 마지막 5일 (10.31~11.04) 전체, 0.5~8시간 뒤** (짝 10만 개)

| 모델 | MAE | RMSE |
|---|---|---|
| **LightGBM (날씨 포함)** | 0.108 | **0.238** |
| LightGBM (날씨 제외) | 0.109 | 0.241 |
| XGBoost (같은 조건) | 0.109 | 0.240 |
| 현재값 유지 | **0.089** | 0.255 |
| 과거 같은 시간대 평균 | 0.122 | 0.262 |

- LightGBM과 XGBoost는 거의 같아 학습이 빠른 LightGBM을 쓴다.
- 날씨(기온·강수량·습도)를 넣으면 RMSE가 0.241 → 0.238로 조금 좋아진다. 3주 기록이라 날씨 변화 폭이 작아 효과도 작다.
- 만차 예측 AUC 0.89.
- 중요 변수: 과거 같은 시간대 평균(평일/주말)이 대부분이다. 충전소별 시간대 습관이 가장 큰 단서다.

## 사이트 연동

- 충전소 상세에 1시간 후 예상 이용률·만차 확률·예상 상태·예상 단가 표시
- 요금 정책의 **"1시간 후 예측으로 요금 판정"**을 켜면 지도·목록의 단가가 예측 상태 기준 배수로 계산된다 (지도 색과 대체 안내는 지금 상태 그대로). 현재 혼잡에 반응하는 요금제를 미래 혼잡을 반영하는 요금제로 바꿔 볼 수 있다.

### 한계

- 1시간 검증이 아직 3일치다. 15분 수집이 쌓이면 성능 평가(하루 한 번 자동)가 그 날짜들을 계속 더한다.
- 기록이 3주라 요일 패턴은 평일/주말로만 나눴다. 행사·교통량 같은 외부 변수는 없다.
